# MercuryOps

MercuryOps — pet-проект на Go для управления товарами, складскими остатками и заказами. Проект строится вокруг бизнес-логики: доменные правила не зависят от HTTP, базы данных или конкретного фреймворка.

## Что уже реализовано

- создание товара с проверкой названия, цены и SKU;
- приём товара на склад;
- расчёт доступного остатка;
- резервирование и освобождение товара;
- отгрузка только из зарезервированного остатка;
- создание заказа в статусе `draft`;
- переходы заказа `draft → confirmed` и `draft → cancelled`;
- unit-тесты для основных и ошибочных сценариев.

## Стек

- Go 1.26;
- стандартная библиотека;
- `testing` для unit-тестов.

## Структура проекта

```text
cmd/mercuryops/       точка запуска приложения
internal/product/     товары и их валидация
internal/inventory/   складской остаток и движение товара
internal/order/       заказы и переходы между статусами
```

## Основные правила

Склад хранит фактический (`onHand`) и зарезервированный (`reserved`) остаток. Доступное количество рассчитывается как:

```text
available = onHand - reserved
```

Резервирование не уменьшает физический остаток. Освобождение возвращает товар в доступный остаток, а отгрузка одновременно уменьшает `onHand` и `reserved`.

Новый заказ создаётся в статусе `draft`. Подтвердить или отменить можно только черновик; повторные переходы отклоняются.

## Текущий этап

Сейчас проект представляет собой покрытое тестами доменное ядро без базы данных и HTTP API. Один заказ пока содержит одну товарную позицию.

Ближайшие задачи:

1. Добавить несколько позиций в заказ.
2. Связать подтверждение заказа с резервированием склада.
3. Добавить in-memory repository и application service.
4. Подключить PostgreSQL и миграции.
5. Реализовать HTTP API, авторизацию и изоляцию данных компаний.
6. Добавить аудит, фоновые события, Docker и CI/CD.
